# 类型绑定架构说明（UE 反射 ↔ AngelScript 的桥接）

> 对应源码（`Engine/Plugins/Angelscript/Source/AngelscriptCode/`）：
> - `Public/Private/AngelscriptType.h / .cpp` —— `FAngelscriptType`（类型操作接口）与 `FAngelscriptTypeUsage`（带限定的类型使用）
> - `Public/Private/AngelscriptBinds.h / .cpp` —— 绑定构建器 `FAngelscriptBinds`、thunk 生成、`FBind` 静态自注册
> - `Private/Binds/Bind_BlueprintType.cpp`（87KB）—— 全量 UClass 的动态绑定、TypeFinder 注册、属性/继承绑定
> - `Private/Binds/Bind_BlueprintCallable.cpp / Bind_BlueprintEvent.cpp` —— UFUNCTION → AS 函数（直调 / 事件覆写两条路）
> - `Private/AngelscriptBindDatabase.cpp` —— `Binds.Cache`（绑定信息序列化，cook 产物）
> - 反向（脚本类 → UE 反射）：`Private/ClassGenerator/`（见《LSP架构说明》与本文 §6）
>
> 前置阅读：《AngelScript虚拟机架构说明》§7（caller 委托制——绑定的调用侧）、《Precompile与StaticJIT架构说明》§4.5。

## 0. 一句话总览

绑定层的核心是一个**双重分发的类型操作接口**（`FAngelscriptType`）：每个"可出现在脚本里的 C++/UE 类型"实现它，AngelScript 引擎与 UE 反射两侧的所有需求（注册声明、属性匹配/创建、GC 引用、拷贝/构造、调用边界marshaling、调试取值、StaticJIT 的 C++ 形态）都经由这个接口落到具体类型实现上。方向有两个：**C++ → AS**（启动时把 UClass/UFunction/UProperty 绑进 asIScriptEngine）与 **AS → C++**（脚本类由 ClassGenerator 反向生成 UASClass/UASFunction/FProperty）。

## 1. FAngelscriptType：类型操作接口（AngelscriptType.h:23）

约 60 个虚函数，按用途分组：

| 组 | 代表方法 | 用途 |
|---|---|---|
| 命名 | `GetAngelscriptTypeName` / `GetAngelscriptDeclaration(Usage, Mode)` | 生成 AS 侧声明；Mode 区分成员变量/函数返回值/参数等**上下文相关声明** |
| UE 反射关联 | `GetClass` / `GetUnrealStruct` / `GetAngelscriptTypeInfo` / `GetData` | 双向指针：UClass ↔ asITypeInfo |
| 属性匹配/创建 | `MatchesProperty(Usage, Property, MatchType)` / `CanCreateProperty` / `CreateProperty(Usage, Params)` | FProperty ↔ AS 类型互认；MatchType 分 TypeFinder/OverrideArgument/InContainer 四种语境 |
| GC | `HasReferences` / `EmitReferenceInfo` / `NeverRequiresGC` | 给 ClassGenerator 生成 GC schema（UE::GC::FSchemaBuilder） |
| 值语义 | `NeedCopy/CopyValue`、`NeedConstruct/ConstructValue`、`NeedDestruct/DestructValue`、`GetValueSize/Alignment`、`CanHash/GetHash`、`IsOrdered/CompareOrder` | 是否可 POD 直拷、是否平凡，决定 VM 对该类型的 asOBJ_APP_CLASS flags 与行为绑定 |
| **调用边界** | `CanBeArgument` / `SetArgument(Usage, idx, Context, FFrame& Stack, Data)`、`CanBeReturned` / `GetReturnValue` | **UFunction 调用脚本时的参数 marshaling**：从 UE 的 FFrame 参数栈读值压进 AS context，返回值反向 |
| 默认值 | `DefaultValue_UnrealToAngelscript` / `AngelscriptToUnreal` / `AngelscriptFallback` | UPROPERTY meta 字符串 ↔ AS 声明默认值互译 |
| 调试 | `GetDebuggerValue/Scope/Member`、`GetStringIdentifier` | DAP 变量视图（连接《DAP调试架构说明》） |
| StaticJIT | `GetCppForm(Usage, FCppForm&)` | 类型 → C++ 类型名/头文件，转译代码生成的依据 |
| 杂项 | `IsObjectPointer` / `IsUnresolvedObjectPointer` / `CanBeTemplateSubType` / `IsTypeEquivalent` / TOptional 三件套 | GC、模板子类型合法性、热重载等价比较 |

静态注册表（类型数据库）提供四个查找入口 + 扩展机制：

```
FAngelscriptType::GetByClass(UClass*)          // UClass → 类型实现
FAngelscriptType::GetByProperty(FProperty*)    // FProperty → 类型实现（不含限定）
FAngelscriptType::GetByAngelscriptTypeName()   // AS 名字 → 类型实现
FAngelscriptType::GetByData(void*)             // 自定义 key
Register / RegisterAlias / RegisterTypeFinder(Finder)   // 注册、别名、属性探测器
```

**TypeFinder 机制**（:79）：`TFunction<bool(FProperty*, FAngelscriptTypeUsage&)>`，处理"FProperty 不直接对应一个类型"的场合——`FObjectProperty` 指向哪个 FUObjectType 取决于 PropertyClass、`FWeakObjectProperty`→`FWeakObjectPtrType<子类型>`、`CPF_TObjectPtr`→`FObjectPtrType<子类型>` 等都靠 finder 填 `Usage.Type + SubTypes`（Bind_BlueprintType.cpp:2509+ 注册）。

## 2. FAngelscriptTypeUsage：带限定的"类型使用"

```cpp
struct FAngelscriptTypeUsage
{
    TArray<FAngelscriptTypeUsage> SubTypes;   // 模板子类型递归
    TSharedPtr<FAngelscriptType> Type;        // 基类型
    bool bIsReference, bIsConst;              // 限定符
    union { asITypeInfo* ScriptClass; FProperty* UnrealProperty; int32 TypeIndex; };
};
```

它是贯穿全系统的"类型令牌"：绑定签名、属性匹配、ClassGenerator、LSP 的 `FAngelscriptTypeUsage`（名字相同，是 LSP 侧的对应物）都以它为单位。八个 `From*` 工厂覆盖所有来源——`FromProperty(FProperty*)` 是 UE→AS 的主干（AngelscriptType.cpp:239）：

```
FromProperty:
  1. 逐个 TypeFinder 问询，命中即得 Type+SubTypes
  2. 否则 GetByProperty 直查
  3. CPF_ConstParm / APF_CppConst → bIsConst
  4. 引用判定分两支：APF_RuntimeGenerated（脚本生成属性）信 CPF_ReferenceParm；
     C++ 属性不信 UFUNCTION 标志（注释：有些函数设置不正确），信 APF_CppRef
```

`AngelscriptPropertyFlags`（APF_*）是 fork 给 FProperty 加的字段——在 cook/编辑期把"这个属性在脚本世界里的限定符"直接存进反射对象，运行时零推断。

## 3. 绑定框架：FAngelscriptBinds 与静态自注册

### 3.1 FBind 事件与排序执行

每个 `Bind_*.cpp` 用 `AS_FORCE_LINK const FAngelscriptBinds::FBind Name(EOrder, [](){...})` 声明绑定块——静态对象在进程启动时把 lambda 塞进全局数组，`FAngelscriptManager::BindScriptTypes()` → `CallBinds()`（AngelscriptBinds.cpp:39）**按 EOrder 排序后依次执行**：

```
Early（声明期）: 所有类型的 ReferenceClass/ValueClass 注册 —— 先把类型骨架全部立起来
Late（实现期）: Method/Property/Constructor 等成员绑定 —— 可引用 Early 注册的任何类型
Late±N       : Bind_BlueprintType 用 Late+100 收尾（动态 UClass 绑定依赖前面全部就绪）
```

两阶段是硬需求：AS 的 `RegisterObjectMethod` 需要签名里的类型已存在。`AS_FORCE_LINK`（GCC `[[gnu::used, gnu::retain]]`）防止链接器 GC 掉"没人引用"的静态注册对象。

### 3.2 构建器 API

```cpp
auto Binds = FAngelscriptBinds::ValueClass<FVector>("FVector", Flags);  // 值类型（asOBJ_VALUE）
                FAngelscriptBinds::ReferenceClass("AActor", AActor::StaticClass()); // 引用类型
Binds.Method("float Size() const", METHOD_TRIVIAL(FVector::Size));
Binds.Property("float X", &FVector::X);          // 成员按偏移直曝
Binds.Constructor("void f(float, float, float)", FUNC(FVector_Factory));
Binds.Factory(...) / Destructor(...) / TemplateCallback(...)
```

- **ReferenceClass**（AngelscriptBinds.cpp:46）：`asOBJ_REF | asOBJ_NOCOUNT | asOBJ_IMPLICIT_HANDLE`——UObject 引用计数由 GC 管，AS 侧不管；隐式句柄让脚本里 `AActor` 就是 `AActor*`。
- **ValueClass\<T>**：`Flags.ExtraFlags |= asGetTypeTraits<T>()`（模板 traits 自动推导 CDAK 构造/析构/拷贝标志）+ `asOBJ_APP_CLASS_CDAK` 兜底；对齐取 `alignof(T)` 或 `UScriptStruct::GetCppStructOps`。

### 3.3 caller thunk 的自动生成（AS_CALLER）

《VM 架构说明》§7 说过：这个 fork 的所有系统函数调用走 `asFunctionCaller` 委托。绑定层用**模板魔术**让委托自动产生（AngelscriptBinds.h:43, 89-115）：

```cpp
#define AS_CALLER(Function) FASBindFunctionPointers::GetThunk<decltype(Function), Function>(Function)
// GetThunk<FP, FP>(ReturnType(*)(ParamTypes...))
//   → { asSFuncPtr(引擎侧函数指针), ASAutoCaller::RedirectFunctionCallerThunk<FP, FP, Ret, Params...> }
// GetThunk<FP, FP>(ReturnType(ObjectType::*)(Params...) [const])
//   → { asSMethodPtr, ASAutoCaller::RedirectMethodCallerThunk<...> }
```

`GetThunk` 以**编译期函数指针值**为模板参数，实例化出该函数专属的 `Redirect*CallerThunk`——thunk 收到 `(函数指针, void** Parameters, void* ReturnValue)` 三元组后按 C++ 语义解包调用。这就是 caller 委托制的生产端：`FUNC()/METHOD()` 宏 = `AS_CALLER(原生指针)`，无需手写任何调用代码。

### 3.4 与 StaticJIT 的联动

`AS_CAN_GENERATE_JIT` 下宏额外展开出函数名字符串与 trivial 标志（AngelscriptBinds.h:50-60）：

```cpp
#define METHODPR(Ret,Cls,Name,Args) AS_CALLER((Ret(Cls::*)Args)&Cls::Name), AS_STRINGIZE(Name), false
#define METHOD_TRIVIAL(Cls,Name)    AS_CALLER(&Cls::Name), AS_STRINGIZE(Name), true
```

`Method(Signature, Pointers, FunctionName, bTrivial)` 重载把 `(名字, 是否平凡)` 报给 `SCRIPT_NATIVE_METHOD`——StaticJIT 转译系统调用时按名字解析 `FJitRef_SystemFunctionPointer`，trivial 函数（无 GC 影响、无异常）可被更激进地内联。`GetCppForm` 则给类型提供转译代码里的 C++ 拼写。

## 4. UClass 的动态绑定（C++ → AS 主干）

### 4.1 两条数据源：编辑器反射 vs Binds.Cache

```
编辑器（无 AS_USE_BIND_DB）:
  Bind_BlueprintType_Declarations (EOrder::Early):
    for (UClass* Class : TObjectRange<UClass>())     // 全量反射遍历
        if (ShouldBindEngineType(Class))             // BlueprintType 等过滤
            BindUClass(Class, GetBoundClassName(Class));   // U/A 前缀规则

打包版（AS_USE_BIND_DB = !WITH_EDITOR）:
  cook commandlet 期间绑定一遍并 FAngelscriptBindDatabase::Save("Binds.Cache")
  （类清单 UnrealPath/TypeName、方法表、属性表、命名数据序列化）
  运行时 Load：Early pass 里 FindObject<UClass>(UnrealPath) 逐个复活
  → 无反射遍历、无 UObject 迭代，启动快且不依赖编辑器数据
```

缺 Cache 直接 Fatal（AngelscriptBindDatabase.cpp:113-116）——cook 流程必须产出它。Header 伴生文件（`.Cache.Headers`）存 C++ 头文件路径，供 LSP 的 GoToDefinition 跳到原生代码（连接《LSP架构说明》）。

### 4.2 Late pass：成员绑定与继承

`Bind_Defaults`（EOrder::Late+100）分两步：

1. **方法**：每个类查 `FAngelscriptBindDatabase` 的方法表 → `Class->FindFunctionByName` 得 UFunction →
   - `FUNC_BlueprintEvent | FUNC_NetFuncFlags` → **BindBlueprintEvent**（脚本可覆写的事件，见 §5.2）
   - 其余 → **BindBlueprintCallable**（脚本直接调的 C++ 函数，见 §5.1）
2. **继承**：沿 UClass 的 SuperClass 链上溯，找到第一个已绑定的父类后 `ScriptType->CopySystemType(InheritScriptType)`——AS 侧父类成员直接整体复制，不需要逐成员 re-bind。另一实现（编辑器路径 :1361 `FClassVisiter::Visit`）先递归访问父类保证绑定顺序。

### 4.3 属性绑定（BindProperties，:1039）

```
TFieldIterator<FProperty> 遍历:
  CPF_EditorOnly 且非编辑器脚本 → 跳过
  GetPropertyBindParams(Property)  → FBindParams（ScriptName meta、BlueprintReadOnly/WriteOnly → bCanRead/bCanWrite）
  FAngelscriptTypeUsage::FromProperty(Property)     ← §2 工厂
  已有 Get/Set 访问器 → 跳过自动属性
  Usage.Type->BindProperty(Usage, Params, Property) 优先（类型自定义绑定，如委托）
  否则按偏移注册普通属性（getter/setter 走 offset 或 FProperty 地址）
```

属性 meta 的 `ScriptName` 支持分号分隔多别名；`ToolTip` meta 进 `FAngelscriptDocs` 供 LSP 悬停。

## 5. UFunction 的两条绑定路径

### 5.1 BindBlueprintCallable：脚本调 C++（Bind_BlueprintCallable.cpp:18）

```
过滤: 必须 FUNC_Native + 有 ASReflectedFunctionPointers[FunctionName].CallerPtr
      （NotInAngelscript / BlueprintInternalUseOnly metadata 排除）
FAngelscriptFunctionSignature Signature(InType, Function):   // 签名翻译
  返回值/参数逐个 FAngelscriptTypeUsage::FromProperty
  bAllTypesValid 检查——任何一个类型绑不了就整体放弃该函数
FunctionPointers.FunctionCaller = FuncInMap->CallerPtr        // caller 来自反射函数指针表
→ Binds.Method(BuildFunctionDeclaration(...), FunctionPointers)
```

`ASReflectedFunctionPointers`（UClass 上的 map）由**UE 生成的代码**在注册 UFunction 时填入（UHT/模块生成的 `AS_REFLECTED_FUNCTION` 宏把 UFUNCTION 的 native 指针 + 自动 caller thunk 挂表）——这就是"带 caller 的注册"在反射世界的等价物。调用时走《VM 架构说明》§7.3 的 `CallFunctionCaller` 桥，参数按 `parameterOffsets` 打包。

### 5.2 BindBlueprintEvent：C++ 调脚本（事件覆写）

`FUNC_BlueprintEvent`/网络 RPC 绑成 AS 类的**可覆写方法**（virtual）：脚本里 `override` 的函数注册到 UASFunction；引擎触发事件时经 UFunction 的 Parms 结构 → `UASFunction` 的反射调用入口 → `MakeRawJITCall_*`/VMEntry 进脚本（连接《Precompile与StaticJIT》§10 的三形态入口与《DAP 调试架构》）。参数 marshaling 正是 `FAngelscriptType::SetArgument(FFrame& Stack, ...)`——从 UE 的 FFrame 参数栈读值压 AS context。脚本类成员函数对 Blueprint 侧暴露为 `BlueprintOverride`。

## 6. 反向：脚本类 → UE 反射（ClassGenerator）

（细节属 ClassGenerator 主题，这里只给类型绑定视角的闭环）

脚本 `class AMyActor : AActor` 编译后：

- 每个脚本类生成 **UASClass**（UClass 子类）——`FUObjectType` 的 `Usage.ScriptClass != nullptr` 分支描述它们（`Class == nullptr`，`ScriptClass->GetUserData()` 反查 UASClass，Bind_BlueprintType.cpp:130-135）；
- 脚本成员变量经 `Usage.CreateProperty`（如 FUObjectType → `FObjectProperty`、`TSubclassOf` → `FClassProperty`，:118-136）生成**真实 FProperty**——蓝图/序列化/GC 全部原生可用；
- GC 引用经 `Usage.EmitReferenceInfo` 写进 UASClass 的 GC schema；
- 脚本函数生成 **UFunction**（UASFunction），Parms 结构的每个参数同样来自 CreateProperty；
- 热重载时类型等价性靠 `IsTypeEquivalent`（脚本类按 `asCObjectType::name` 比较，:76-95）判断成员是否需要迁移。

## 8. 值得注意的设计总结

| 设计 | 动机 |
|---|---|
| 单一 FAngelscriptType 接口承载全部双向操作 | 类型差异（值/引用/指针/模板）只体现在一个实现类里；引擎、ClassGenerator、调试器、StaticJIT 四个消费者零特判 |
| TypeFinder 链处理 FProperty → 限定类型 | ObjectProperty/TObjectPtr/WeakPtr/SubclassOf 的目标类型藏在 PropertyClass 里，直查表搞不定；finder 还能填 SubTypes 形成模板组合 |
| APF_* 标志预计算进 FProperty | 引用/常量限定在绑定时定死存反射对象，运行时不再推断；顺带绕开"UFUNCTION 标志不可信"的引擎脏数据 |
| FBind 静态自注册 + EOrder 两阶段 | Early 全量声明/Late 全量成员，解决类型间前向引用；AS_FORCE_LINK 对抗链接器 GC |
| AS_CALLER 模板 thunk 自动产 caller | 与 VM 的"无原生调用约定"配套：每个绑定函数在编译期实例化专属调用 thunk，绑定代码零手写 ABI |
| Binds.Cache 双数据源 | 打包版免反射遍历（cook 时定型），编辑器版保持动态（开发迭代）；同时给 LSP 提供原生头文件索引 |
| CopySystemType 整类继承 | AS 侧继承用成员快照复制而非逐项查找，运行时成员访问零层级开销 |
| caller 信息藏在 UClass 的 ASReflectedFunctionPointers | UFunction 的 native 指针→caller 映射随反射注册生成，BindBlueprintCallable 按表取用 |
| GetCppForm / 名字+trivial 双轨上报 | 同一类型系统同时服务运行时（VM）与离线（StaticJIT 转译）两个执行引擎 |
